# 오토런 사용자 경험 시나리오 매트릭스

이 문서는 오토런을 한 번에 하나만 실행한다는 불변조건 아래, 사용자가 실제로 이동·중단·복구하는 조합을 검증한다. 버튼 활성 여부는 화면을 열어 둔 시간이나 메모리 상태가 아니라 영속 Job 스냅샷의 `active`, `paused`, `terminal`, `waitingForUser`, `userStopped` 값으로 결정한다.

## 새 작업과 작업 전환

| 상황 | 기대 동작 | 검증 |
|---|---|---|
| 작업 이력이 없음 | 프로젝트 기본값만 표시하고 요구사항·모델·추론·현재 동작·로그는 빈 새 작업 화면 | 단위/UI |
| 완료 Job만 있음 | 확인 없이 새 Job 시작 | 단위/UI |
| 수동 일시정지 Job이 있음 | 기존 스냅샷을 보존한 뒤 새 Job 즉시 시작 | 단위/기기 |
| 오류·DOM 변경·전송 불명확 Job이 있음 | 오류 Job을 재개 가능 상태로 보존한 뒤 새 Job 시작 | 단위/기기 |
| 사용자 조치 대기 Job이 있음 | 대기 Job을 보존한 뒤 새 Job 시작 가능 | 단위/기기 |
| 다른 Job이 실제 실행 중 | 새 Job 생성 금지, 현재 Job ID와 `현재 작업 열기` 제공 | 단위/UI |
| 실행 중인 Job A에서 과거 Job B 재개 | 자동 전환하지 않고 A를 직접 일시정지/중지하도록 안내 | 단위/UI |
| 일시정지 A에서 B 재개 | A 스냅샷 보존 확인 후 B 복원·DOM 재구성 | 단위/기기 |
| 기존 Job 보존 쓰기 실패 | 새 Job으로 덮어쓰지 않고 보존 실패 안내 | 소스/기기 |
| 목록에서 사라진 Job 딥링크 | 현재 Job을 대신 표시하지 않고 `작업 없음` 표시 | 단위/UI |

## 버튼과 종료 의미

| 영속 상태 | 재개 | 일시정지 | 중지 | 삭제 | 설명 |
|---|---:|---:|---:|---:|---|
| 실행 중 | 비활성 | 활성 | 활성 | 비활성 | 중복 재개나 실행 중 숨김 방지 |
| 수동 일시정지 | 활성 | 비활성 | 활성 | 활성 | 다시 실행하거나 영구 중지 가능 |
| 오류/불명확 | 활성 | 비활성 | 활성 | 활성 | 재개는 관찰 전용 reconciliation |
| 사용자 조치 대기 | 활성 | 비활성 | 활성 | 활성 | 재개가 `AUTOMATION_USER_RESOLVED` 전송을 담당 |
| `AR_DONE` | 비활성 | 비활성 | 비활성 | 활성 | 성공 완료 |
| `AR_PAUSE` terminal | 비활성 | 비활성 | 비활성 | 활성 | Orchestrator가 종료시킨 일시정지 terminal |
| `AR_ABORTED` | 비활성 | 비활성 | 비활성 | 활성 | 중단 terminal |
| 사용자 중지 | 비활성 | 비활성 | 비활성 | 활성 | 앱에서 재개 불가, 원격 대화/Drive는 유지 |
| 레거시 요약만 존재 | 비활성 | 비활성 | 비활성 | 활성 | 전체 workspace가 없어 fail-closed |

`중지`는 확인/취소 대화상자를 거치며 비가역적인 앱 내 terminal 전환이다. 계속할 가능성이 있으면 `일시정지`를 사용한다. `작업 삭제`는 앱 목록에서만 숨기며 대화, Drive 파일, Job ID 사용 이력은 삭제하지 않는다.

## 입력과 화면 이동

| 상황 | 기대 동작 | 검증 |
|---|---|---|
| 새 작업 화면을 반복해서 엶 | 프로젝트 주소만 기본값으로 재사용 | 단위/UI |
| 요구사항 입력 중 회전/일시적 재생성 | 같은 새 작업 화면 인스턴스에서는 임시 입력 복원 | UI |
| 새 작업을 나갔다 다시 새로 엶 | 이전 Job 요구사항·로그·상태를 불러오지 않음 | 단위/기기 |
| 잘못된 프로젝트 주소를 입력하고 화면 이탈 | 마지막 유효 기본 프로젝트를 덮어쓰지 않음 | 단위/UI |
| 유효 프로젝트 주소로 변경 후 이탈 | 다음 새 Job의 기본 프로젝트로 저장 | 단위/UI |
| 실행 중 기본 설정 변경 | 현재 Job 스냅샷은 불변, 다음 Job부터 적용 | 단위/기기 |
| 매우 긴 요구사항 | 200,000자까지 허용하고 이력 요약은 별도 제한 | 단위 |
| 목록에 Job이 많음 | 완료 Job을 자동 폐기하지 않고, 카드에는 최근 수행 항목 4개만 표시 | 단위/UI |

## 프로세스·네트워크·ChatGPT 상태

| 상황 | 기대 동작 | 검증 |
|---|---|---|
| Chat 제출 직전 재시작 | 영속 `SUBMITTING`에서 자동 재제출하지 않고 DOM 관찰 | 단위/기기 |
| Chat 제출 직후 URL 미확정 재시작 | 기존 사용자 턴/현재 URL을 확인해 같은 대화 확정 | 단위/기기 |
| 새 conversation URL이 사용자 턴 DOM보다 먼저 표시됨 | 최대 20초 관찰만 하고 재전송 금지, 고유 Job 표식으로 확인하며 계속 불명확하면 안전 정지 | 단위/기기 |
| Work 설정 중 재시작 | 모델·추론 readback 전에는 프롬프트 미제출 | 단위/기기 |
| Work 첫 제출 직후 재시작 | 사용자 턴 존재 여부 확인, 불명확하면 일시정지 | 단위/기기 |
| 로그인 만료 | 로그인 필요 오류로 정지, 중복 대화/메시지 금지 | 단위/기기 |
| 프로젝트 불일치 | URL 캡처 거부 및 명시 오류 | 단위/기기 |
| Chat과 Work가 같은 conversation | endpoint 확정 거부 | 단위 |
| 모델/추론 선택값 readback 불일치 | fallback 없이 오류 | 단위/기기 |
| 네트워크 단절 | 무부작용 재시도만 수행, 제출 결과 불명확은 fail-closed | 단위/기기 |
| DOM 변경 | 명시 오류와 디버그 로그, 임의 클릭 금지 | 단위/기기 |

## 예약 선점과 로그

| 상황 | 기대 동작 | 검증 |
|---|---|---|
| bootstrap 어느 단계에서든 예약 도착 | 예약 우선, 오토런 상태를 저장하고 WebView 양보 | 단위/회귀 |
| 제출 결과 불명확 중 예약 도착 | 재제출 없이 예약 처리 후 관찰 복구 | 단위/회귀 |
| 예약 완료 | 직전 Job의 마지막 확정 상태부터 재개 | 단위/기기 |
| 작업 A/B 로그 열기 | 각 Job ID 전용 실행·디버그 로그만 표시 | 단위/기기 |
| 로그 쓰기 실패 | 중계/예약 실행은 계속되고 실패 횟수만 진단에 남김 | 단위 |
| 앱에서 Job 숨김 | 해당 카드만 사라지고 다른 Job·예약·원격 산출물은 유지 | 단위/UI |

릴리즈 전에는 이 매트릭스의 단위/소스 항목을 자동화하고, `기기` 항목의 핵심 경로를 설치된 최종 후보 APK에서 새 Run ID와 로그로 다시 확인한다.

# ChatGPT Prompt Scheduler for Android

ChatGPT 웹 세션에 예약 프롬프트를 자동 전송하는 독립 Android 앱입니다. Chrome 확장프로그램이나 외부 브라우저에 의존하지 않습니다.

- versionName: `2100000000`
- versionCode: `2100000000`
- Application ID: `com.shaterguy.chatgptpromptscheduler`
- Android 8.0 이상

v2100000000은 v0.1.21의 기능 코드와 동작을 그대로 유지하면서, 사용자 실기기 재설치 성공이 확인된 최대 versionCode/versionName으로 버전 메타데이터만 상향한 정식 릴리스입니다.

일반·프로젝트·기존 대화, Chat·Work 모드, 일회성·매일·매주·분 간격 반복, 기존 입력 교체, 설정 JSON 내보내기·가져오기, 스마트폰·태블릿 UI를 지원합니다.

기능 기준은 v0.1.21과 동일합니다. Protocol 3.3 오토런은 앱이 bootstrap 권한을 가집니다. Job ID를 자동 생성하고 지정 프로젝트에 실행 전용 일반 Chat을 만든 뒤, 첫 `AR_SEND_WORK` 때 같은 프로젝트에 Work를 지연 생성합니다. 두 대화의 실제 URL은 첫 사용자 턴과 프로젝트 경로를 함께 확인한 뒤 저장합니다. 기존 예약 생성·저장·알림·실행 경로와 JSON 형식은 변경하지 않았습니다.

## 오토런 중계 사용

1. 일반 Chat에서 작업을 충분히 논의하고 최종 `(오토런) ...` 요구사항을 준비합니다.
2. 앱에서 프로젝트 주소와 Work 모델/추론 기본값을 설정하고 요구사항을 붙여넣은 뒤 `오토런 시작`을 한 번 누릅니다.
3. 앱은 Job ID를 영속 생성하고 프로젝트의 새 일반 Chat에 요구사항과 `[AUTOMATION_BOOTSTRAP 3.3.2 ...]` metadata를 전송합니다.
4. Orchestrator의 최초 `AR_SEND_WORK`를 받으면 새 Work를 만들고 선택 모델/추론값의 실제 적용을 확인한 뒤 현재 Step을 전송합니다.
5. 이후 각 응답의 마지막 Protocol 3.3 제어 신호에 따라 두 대화를 중계합니다. 잘못된 프로젝트·대화, 로그인 필요, 선택값 미확인 또는 제출 결과 불명확 상태에서는 자동 재전송하지 않습니다.

`오토런 중계 열기`는 작업 이력 화면을 먼저 엽니다. 상단 `새 작업`에서 새 실행 설정으로 이동하며, 모든 Job 카드는 `작업 열기`로 독립 보존된 상세 작업공간에 들어갈 수 있습니다. 앱은 새 Job이 생겼다는 이유로 완료 이력을 자동 폐기하지 않습니다. 상세 화면에는 해당 Job의 원본 요구사항, 프로젝트·대화 연결, 모델·추론, Step/Round, 마지막 신호·전달·오류와 해당 Job만의 실행 로그(사용자용 요약) 및 디버그 로그(redacted JSONL)가 표시됩니다. Work 설정 검증 시에는 요청 모델/추론과 실제 UI readback 값을 `WORK_PREFERENCES_VERIFIED` 로그로 남깁니다. 카드에는 최근 수행 항목 4개를 간결하게 표시하고 전체 로그는 별도 화면에서 확인합니다. 검증된 `AR_DONE`만 성공 완료로 판정하며 `AR_PAUSE`와 `AR_ABORTED`는 각각 일시정지·중단 terminal로 구분합니다. terminal Job의 재개·일시정지·중지 버튼은 비활성화되고, 미완료 과거 Job은 전체 복구 스냅샷이 있을 때만 재개할 수 있습니다. 로그 버튼은 완료 여부와 무관하게 계속 동작합니다. `작업 삭제`는 확인/취소 대화상자를 거쳐 앱의 목록·상세 화면에서만 숨기며 ChatGPT 대화와 Drive 파일은 건드리지 않고 Job ID도 재사용하지 않습니다. 작업별 디버그 로그는 앱 내부에서 별도 파일로 제한 보관합니다.

사용자가 현재 Job을 수동으로 `일시정지`하면 그 Job의 전체 스냅샷을 저장하고 단일 중계 실행 슬롯을 양보하므로 새 Job을 시작할 수 있습니다. 일시정지·오류·전송 불명확·사용자 조치 대기 Job의 `재개`와 `중지`는 활성이고, 실제 실행 중 Job은 `일시정지`와 `중지`만 활성입니다. `중지`는 확인/취소 대화상자를 거쳐 앱 내 재개 불가 terminal로 전환하므로 나중에 계속하려면 `일시정지`를 사용해야 합니다. 다른 Job이 실행 중일 때 과거 Job의 `재개`를 누르면 서비스를 자동 전환하지 않고 현재 Job ID와 `현재 작업 열기`를 표시합니다. 사용자가 현재 Job을 직접 일시정지 또는 중지한 뒤 원하는 Job을 재개합니다.

새 Job 시작 시 다른 비종료 Job이 실제 실행 중이면 시작하지 않고 해당 Job ID와 `현재 작업 열기`를 표시합니다. 기존 Job이 수동 일시정지, 오류, 전송 불명확 또는 사용자 조치 대기로 실행 슬롯을 양보했다면 그 Job의 전체 스냅샷 저장 성공을 확인한 뒤 새 Job 하나를 시작합니다. 저장 실패 시 기존 Job을 덮어쓰지 않습니다. 새 작업 화면에서 잘못 입력한 프로젝트 주소는 화면을 나가더라도 마지막 유효 기본 프로젝트를 덮어쓰지 않습니다.
6. `[AR_USER_ACTION_REQUIRED JOB S### R### ACTION_ID]`가 오면 사용자 조치 대기 알림을 표시합니다. 사용자가 조치를 마치고 `재개`를 누르면 앱이 `[AUTOMATION_USER_RESOLVED JOB ACTION_ID]`를 일반 Chat에 보내 재검증을 요청합니다. 별도의 `처리 완료` 버튼은 사용하지 않습니다.

프로젝트·요구사항·Work 모델·추론값은 Job 시작 시 스냅샷으로 고정됩니다. 기본 설정 변경은 다음 Job부터 적용됩니다. 실행 중 Job ID와 자동 획득한 두 대화 URL은 상태 화면에서 확인할 수 있습니다.

오토런 중계는 선택 기능입니다. 사용하지 않으면 기존 예약 기능의 동작과 데이터 형식에 영향을 주지 않습니다.

상태·화면 이동·다중 Job·프로세스 재시작·오류·예약 선점 조합의 릴리즈 검증 기준은 [`docs/AUTORUN_UX_SCENARIO_MATRIX.md`](docs/AUTORUN_UX_SCENARIO_MATRIX.md)에 정리되어 있습니다.

v0.1.2 이후 APK는 동일한 고정 인증서로 서명되어 덮어쓰기 업데이트를 지원합니다.
